# v0.5.0

The build Action supports `cache: github` to restore and save the managed Bunko cache, with configurable keys and cache-hit outputs. Its default-on job summary shows phase timings, cache results, stored layer sizes and publication details on success or failure; `summary: 'false'` disables it. Summary writes are bounded, escaped and scrubbed for known credential patterns. Pin an Action commit or tag containing these new inputs. See [CI configuration](https://github.com/sakajunquality/bunko/blob/main/docs/CI.md).

Registry caches now carry dependency closure plan indexes as well as layers. A fresh runner can restore a valid plan from an explicit cache source and skip dependency installation and projection when the referenced layer is available. Missing, malformed or unusable plans fall back to rebuilding. Plan writes follow successful layer exports, respect `--cache-write=false`, and warn by default. `--no-cache`, `--no-local-cache` and determinism verification bypass plan reads. Local and registry cache writers remain trusted build inputs.

Base filesystem inspection is cached locally by immutable base digest and inspection version. Warm inspection reuses validated metadata; base blobs remain deferred until export or publication requires their bytes. `cache-info` and `prune` account for these records. Reports add `base` and `deps-plan` cache events: consumers that aggregate only image layers must select layer kinds explicitly. Registry retention includes the new `bunko-cache-v1-deps-plan-*` tags.

`check-config` and `doctor` no longer hash unsnapshotted workspace sources or traverse workspace dependency trees. Deep checks still read selected source and asset inputs through the build exclusion policy. Unsupported filesystem entries identify their type and selecting asset rule. Missing local OCI blobs now fail through their consumer instead of emitting an early unhandled stream error.

Bun support remains >=1.3.13 <1.5. Registry cache writes still require an explicit destination as introduced in v0.4.0. See [release evidence](https://github.com/sakajunquality/bunko/blob/main/docs/validation/v0.5.0.md) for verified fixture scope and remaining provider/application limits.
