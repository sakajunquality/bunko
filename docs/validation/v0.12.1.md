Every listed publication/CI workflow completed successfully on attempt 1. The merged source tree matches the reviewed preparation tree. The release-preparation PR received zero-context Codex review and a completed CodeRabbit review with no actionable findings; implementation review fixes and unavailable reviews are recorded in their individual PRs.

The final version also passed isolated 0.10.0 and 0.11.0 source-CLI upgrade/rollback scripts using their frozen historical dependencies, shared local and loopback registry caches, a reused report path, current prune and static rebase/base-status checks. This is metadata/cache compatibility evidence, not cloud-registry or container-runtime acceptance. Local cross-architecture Docker tests use emulation where necessary; native CI is separate evidence.

The candidate fixtures used an isolated empty Docker credential configuration for public bases; user credential files were unchanged. npm briefly returned 404 after accepting publication. The original workflow's read-only propagation checks succeeded without republishing.

Cache policy changes cause a one-time cold cache; unknown cache layouts/references inhibit blob reclamation, while unrelated root files remain report-only, and ambiguous legacy locks still require manual recovery. See [cache retention](../CACHE_RETENTION.md) and [format compatibility](../FORMAT_COMPATIBILITY.md). The parser reduces the distributed JavaScript size but increases the measured syntax-scan workload; [PARSER.md](../PARSER.md) records that tradeoff and Babel 7's maintenance deadline. Host Bun support is unchanged. This release does not newly certify additional cloud providers or private workloads.

The independent setup-bunko Marketplace Action is deferred: its immutable published v0.1.1 still defaults to CLI v0.8.0. Updated examples explicitly select CLI v0.12.0; no existing Action tag is moved.
