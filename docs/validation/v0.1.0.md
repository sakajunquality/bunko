# 0.1.0 validation

The candidate JavaScript CLI was prepared with Bun 1.3.11. Its size is 7,863,753 bytes and SHA256 is `c9839f9e0756ae43ba921d754cdd429f85824ee8e5329847342f6fd0ddee4d08`. The stable version promotes rc.5 application build behavior and adds the previously reviewed npm packaging workflow; it does not introduce new application build features.

Candidate checks, publication and published-consumer acceptance are separate gates. The [rc.5 validation](rc5.md) and [initial npm publication](npm-rc5.md) remain historical evidence for their exact versions. The release PR and tag CI repeat the supported Bun matrix. The CLI release, official container and npm package are published independently; their exact source identities and verification results are recorded below.

The private GHCR application conformance run remains blocked by account billing. Private ECR and the external application-machine matrix remain unverified; stable versioning does not change those limits. musl and rebase are tracked separately in issues #53 and #54.

## Candidate results

The full local check passed 523 tests with 6,225 assertions. The exact candidate CLI above passed deterministic compilation and application execution on Linux amd64 and arm64 using host Bun 1.4.2, including verification of the authenticated compiler and base Bun revision. `packages/` has no changes relative to rc.5.

The npm post-publication consumer allows 21 attempts with 15-second delays and bounded individual fetch time, inside a 15-minute job. This follows the several-minute initial metadata propagation delay observed for rc.5; it does not retry or replace a published version.

## Published GitHub CLI

[Release workflow 34317573277, attempt 2](https://github.com/sakajunquality/bunko/actions/runs/34317573277/attempts/2) published the non-prerelease `v0.1.0` on 2026-09-09 from `9ea6580b719049f4afa3fcc8cf3ae2f21b8cc722`. All four jobs passed. The first attempt was canceled before publication after the tag was created on the reviewed PR head rather than its squash commit. [#75](https://github.com/sakajunquality/bunko/pull/75) preserved that commit in main ancestry with an identical source tree, without moving the tag or rewriting history.

[Independent CLI verification](v0.1.0-cli.json) anonymously downloaded the published assets, verified all release subjects against the exact tag/commit, rejected an incorrect source ref and executed the installed version. Its hash and size exactly match the candidate above. GitHub identifies v0.1.0 as the latest non-prerelease release.

## Published official container

[Container workflow 34318353999](https://github.com/sakajunquality/bunko/actions/runs/34318353999) built once, executed both platform builders and their compiled application, attested and promoted the same index. The recipe source is `refs/heads/main` at `72d9ac859fd1c499c2d1856a11891101f25f99df`, separately from the CLI release source above.

[Independent container verification](v0.1.0-container.json) pinned the exact source attestation and anonymously pulled `sha256:1f31e7756fb93926de29b2fce46b5070e35d268b7c48415d27d10725c5e1a8e9`. Both amd64 and arm64 ran version 0.1.0 as default UID/GID 65532 with a read-only filesystem, no network and dropped capabilities. Each image's CLI hash matches the published JavaScript above.

## Published npm package

[npm workflow 34319284314](https://github.com/sakajunquality/bunko/actions/runs/34319284314) published `@sakajunquality/bunko@0.1.0` through GitHub OIDC with npm provenance from main commit `87fe2ffcbe9171ffa4f5f1fb3c7d49f7eeb58d6b`. The package contains the unchanged CLI release above. An earlier attempt failed before publication because npm treated an unprefixed relative tarball path as a GitHub shorthand; [#76](https://github.com/sakajunquality/bunko/pull/76) fixed the path and added an offline publish dry-run to candidate validation.

[Independent npm verification](v0.1.0-npm.json) confirmed anonymous registry download, exact candidate SHA512 integrity, installed CLI SHA256, npm installation, fresh-cache bunx by exact version and `latest`, and a verified registry signature and npm attestation using `npm audit signatures`. `latest` is 0.1.0; `next` remains 0.1.0-rc.5. No existing version was replaced.

[Registry upgrade and rollback verification](v0.1.0-npm-upgrade.json) installed rc.5 → 0.1.0 → rc.5 → 0.1.0 into an isolated npm prefix, checking the executable after every transition. A separate Bun consumer installed stable from the registry and executed it with bunx. These checks used host Bun 1.4.2 and npm 11.12.1; they did not modify a user's global installation.
