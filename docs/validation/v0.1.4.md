## Candidate acceptance

Preparation pins PATH to signed Bun 1.3.11. Frozen installation, typecheck and all 651 tests passed (7,048 assertions). The final CLI is 7,915,612 bytes, SHA256 `47bb047de7f6807458cf39f6aea237768d8760bec23ea90b2565a7f8c8a0081b`. The initial candidate predating the CLI allowlist fix was superseded before tagging.

The exact final CLI built a disposable application using `--asset-cache` and `ghcr.io/hokaccha/spannerdef@sha256:fa7d23b3869e5d635bc6b63e23be062ab603294a1878a3c703282bcea0a20e6f` as an image asset source. Both linux/amd64 and linux/arm64 images executed `/tools/spannerdef` as version 1.5.0, under nonroot, read-only, network-disabled execution with dropped capabilities. The previous main had reproduced the index-selection error against that same pinned image.

The candidate also passed application acceptance on both architectures: migration, worker/database state, HTTP/native dependencies/file reads and shutdown. Runtime-injection checks passed signed release/revision verification, static-base rejection, local OCI base inspection, runtime cache reuse and the native-library boundary on both architectures.

External application-machine acceptance and private ECR remain unverified; the disposable public fixtures do not certify those workloads. musl/rebase and setup Action separation/Marketplace publication remain outside this release.

[Manual Release run 34436676552](https://github.com/sakajunquality/bunko/actions/runs/34436676552) passed prepare and verify-candidate at `c521995c68d10c6e5a0d87d9933b0486209f7b70`. The failed/cancelled jobs passed on rerun; [main CI 34436675311, attempt 2](https://github.com/sakajunquality/bunko/actions/runs/34436675311) completed successfully before tagging.
