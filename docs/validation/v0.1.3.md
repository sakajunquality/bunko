## Candidate identity and correction

The preliminary record incorrectly attributed local nested `bun run` checks and preparation to Bun 1.3.11. The outer executable was 1.3.11, but nested scripts selected PATH Bun 1.4.2. That earlier candidate was 7,912,288 bytes, SHA256 `88a1500996dd4b9b11e856d4d982545c1c77ebfa7c5e34cd3f1c14d3c829e192`; it is not the publication candidate. The discrepancy was detected by comparison before tagging.

After pinning PATH, signed Bun 1.3.11 passed frozen installation, typechecking and all 642 tests (7,011 assertions). Direct preparation with that executable produces a 7,915,461-byte CLI, SHA256 `21cf97ddd662c2db1cf3ec878bf97bb262af93aeef160073fd25a7aa4cb3a707`. It matches [manual Release candidate 34431604904](https://github.com/sakajunquality/bunko/actions/runs/34431604904) byte for byte. Both prepare and verify-candidate passed; independent signed-bundle verification confirmed `refs/heads/main` and the exact main commit above.

The verified manual CLI passed the disposable application fixture on linux/amd64 and linux/arm64: migration, worker, database state, HTTP/native dependencies/file reads and shutdown. That exact CLI also passed runtime-injection checks on both architectures: signed release/revision verification, static-base rejection, local OCI base inspection, runtime cache reuse and the native-library boundary. Publication results follow below.

External application-machine acceptance and private ECR remain unverified; synthetic fixtures do not certify those workloads. musl/rebase and setup Action separation/Marketplace publication remain outside this release.
