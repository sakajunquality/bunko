The glibc/musl × architecture runtime fixtures were not rerun locally for this record; CI on the release PR and main is the evidence for them. Host Bun support and persisted formats remain unchanged. The OCI audit's hardlink identity, runnable artifactType classification, optional document mediaType and nested manifest idle-timeout findings remain open.

The first container run validated linux/amd64 and then rejected linux/arm64 with `Builder image must default to nonroot`. The image was correct: runners now use Docker's containerd image store, where `docker image inspect` without `--platform` returns an empty config when the only pulled platform is not the host's. The untagged candidate index `sha256:a09a2549fca9b97aadbc81e134f721719d03969cc13b68477edfbc2a3c121c79` from that run was never attested or promoted. The published index was rebuilt by the recovery run, so its recipe source is the fix commit rather than the tag commit; the packaged CLI is the unchanged tag release.

CodeRabbit reported no actionable comments on PR #297. No other external review was requested. The independently versioned setup-bunko v0.2.0 retains default CLI v0.12.0; updated examples explicitly select v0.12.6.
