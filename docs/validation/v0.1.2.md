# 0.1.2 validation

PR #89 narrows undeclared-import scanning to entry-point-reachable files. Review follow-ups fix exhausted file iterators across exports patterns, repeated target substitutions, bounded nested manifest reads and queue traversal cost. Regression fixtures cover these cases alongside shipped-test suppression and reachable runtime findings.

At source commit `6157d29542b89457d8a175084966638135099c11`, `bun run check` with signed Bun 1.3.11 passed TypeScript checking and the full suite: 563 tests, 6,480 assertions, zero failures. This includes three review regressions added after the contributor's original 560-test result. [CI run 34415991104](https://github.com/sakajunquality/bunko/actions/runs/34415991104) passed all applicable checks at that commit.

The release CLI prepared with signed Bun 1.3.11 is 7,878,042 bytes, SHA256 `bbe6e1a24edb1254298f1f5b0d892003eb720a97767790ff96a0d091270ff3cc`. That exact CLI produced deterministic compiled images for linux/amd64 and linux/arm64, verified signed compiler and base revisions, and ran as default UID 65532 with declared asset reads, a read-only filesystem, no network and dropped capabilities.

Local Codex and independent Claude reviews found no remaining code blockers. CodeRabbit reviewed both the original code and the corrected source; its findings and resolutions are recorded in PR #89. Final documentation clarifications do not change CLI bytes. Publication and independent consumer evidence follow below. The release checklist gates default promotion on those checks.

The external application observations in the PR are contributor-reported results, not independently repeated here. Synthetic fixtures and official builder acceptance do not certify those workloads. Private ECR and external application-machine acceptance remain unverified; musl/rebase and setup Action separation/Marketplace publication remain outside this release.
