Only post-publication npm verification was rerun after registry propagation exceeded its initial wait. Neither npm publication nor immutable artifacts were repeated or replaced. Other listed publication workflows succeeded on attempt 1.

Zero-context Codex review found no actionable issues and passed 23 focused tests / 201 assertions. CodeRabbit's cancellation-ordering suggestion was independently dismissed: cancellation rejects the operation before retry or acceptance, so it cannot accept mutated inputs. CodeRabbit's subsequent release-metadata review produced no actionable comments.

Complete HTTP 429 responses can be reported by Bun as ambiguous `HTTP 4xx` and are intentionally not retried. The truncated-response/refused-connection recovery fixture passes on Bun 1.4.2. Bun 1.3.13 may continue its own retries rather than exit promptly; its real-network fixture covers successful installation, with bunko retry control tested through controlled subprocesses on both versions. Three installer attempts and three seconds of added backoff do not bound total time spent inside Bun. The reporter's private proxy was not accessed.

Local cross-architecture Docker tests use emulation where needed; native CI is separate evidence. Host Bun support and persisted formats remain unchanged. This release does not resolve the separate OCI audit's hardlink identity, runnable artifactType classification, optional document mediaType and nested manifest idle-timeout findings, or newly certify cloud providers/private workloads.

The independently versioned setup-bunko v0.2.0 retains default CLI v0.12.0. Updated examples explicitly select v0.12.5; `version: latest` selects the current published stable CLI.
