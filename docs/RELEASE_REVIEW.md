# Alpha.2 release review

Claude performed a read-only review of the candidate's source-facing documentation, distribution defaults and workflows. Findings led to corrected zstd/local-resolution contracts, descriptive headings, absolute release-body links, the documented jobs environment variable, and a README with feature guidance before development/license information. Renamed smoke tests retain their assertions. Signing and remote pruning now have package scripts and CI coverage.

The setup Action's `2026-03-10` API header is listed in [GitHub's supported API versions](https://docs.github.com/en/rest/about-the-rest-api/api-versions), and a live authenticated metadata request accepted it. The referenced ko v0.19.1 and BuildKit v0.33.0 releases exist. The [download-artifact v8.0.1 documentation](https://github.com/actions/download-artifact/tree/v8.0.1) retains the v4+ artifact backend contract; the release workflow additionally verifies an actual upload/download round trip in a separate candidate job before publication.

The version, setup defaults and release tag validation agree on `0.1.0-alpha.2`. Candidate preparation does not create a tag, publish a release, change visibility or publish to npm. The repository and dedicated registry validation were private at that review. Identifying but non-secret repository/cloud project names remain in historical validation records; see [public readiness](PUBLIC_READINESS.md).

The follow-up review found no workflow errors; the remaining historical-heading residue was corrected. The [exact local candidate](validation/alpha2-release.json) passed bundle/compile SQLite checks for Linux amd64 and arm64 using the distributed CLI. Its builder fingerprint equals the distributed file's SHA-256. Typecheck and 233 tests passed; links, actionlint and source/history/distribution secret scans passed. [Private GHCR validation](validation/alpha2-ghcr.json) additionally covers native runtime, direct pulls, cache reuse and private metadata signatures at its recorded source checkpoint.

Comparing local and GitHub artifacts exposed a distribution privacy issue: Bun embedded TypeScript's build-time CommonJS directory/file globals. The shared bundle configuration now resolves those globals through runtime `import.meta` properties. Regression assertions reject checkout and TypeScript-installation paths in the CLI, alongside the existing isolated parser, macro-rejection and installation checks. Candidate artifacts created before this fix are superseded.

Claude's focused review confirmed the runtime-global approach preserves the parser and builder-identity behavior. The candidate summary was regenerated from the fixed artifact's four runtime results. An installation-prefix-independent leak assertion also covers symlinked checkouts.
